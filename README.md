# Telegram VPN Bot

Telegram-бот для продажи доступа к VPN на панели **3X-UI**. Бот создаёт ссылку на оплату в YooKassa, проверяет состояние платежа опросом API и после подтверждения продлевает или создаёт клиентский доступ в 3X-UI.

## Возможности

- Регистрация пользователей и реферальные приглашения.
- Тарифы на 30, 90 и 180 дней.
- Оплата через YooKassa с автоматической проверкой статуса (без webhook).
- Выдача и продление VLESS-ключа через API 3X-UI.
- Напоминания об окончании ключа за 5, 3 и 1 день и в день окончания.
- Админ-панель: статистика, ручное добавление доступа и рассылка.
- PostgreSQL для пользователей, платежей и состояния напоминаний.

## Требования

- Python 3.12 или Docker с Docker Compose.
- PostgreSQL, доступный боту по сети.
- Telegram Bot Token и числовой Telegram ID администратора.
- Панель 3X-UI с включённым API и настроенным inbound для VLESS.
- Магазин YooKassa (Shop ID и секретный ключ).

## Установка и настройка

1. Подготовьте PostgreSQL и создайте отдельную БД и пользователя для бота. Передайте приложению DSN вида `postgresql://USER:PASSWORD@HOST:5432/DB_NAME`.
2. Создайте локальный конфигурационный файл:

   ```powershell
   Copy-Item .env.example .env
   ```

3. Заполните `.env` реальными значениями. Не добавляйте этот файл в Git и не отправляйте его в логи или сообщения.
4. Убедитесь, что сервер, где запущен бот, может обращаться к PostgreSQL, 3X-UI и API YooKassa.

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота от BotFather. |
| `ADMIN_IDS` | JSON-массив Telegram ID администраторов, например `[123456789]`. |
| `DATABASE_URL` | DSN PostgreSQL. Бот использует существующую БД и добавляет нужные таблицы через `CREATE TABLE IF NOT EXISTS`. |
| `XRAY_PANEL_URL` | Базовый URL панели 3X-UI, без завершающего `/`, например `https://panel.example.com`. |
| `XRAY_SUB_URL` | Базовый URL подписок; бот добавляет к нему `/<subId>`. |
| `XRAY_API_KEY` | API-токен панели, передаваемый в заголовке `Authorization: Bearer ...`. |
| `XRAY_INBOUND_IDS` | JSON-массив числовых ID inbound, например `[1]`. |
| `YOOKASSA_SHOP_ID` | Числовой идентификатор магазина YooKassa. |
| `YOOKASSA_SECRET_KEY` | Секретный ключ YooKassa. |
| `KEY_DURATION_DAYS` | Совместимый параметр конфигурации; длительность тарифов задаётся отдельно для каждого плана. |
| `PRICE_30_DAYS` | Цена тарифа 30 дней в копейках. `12000` означает 120 рублей. |
| `PRICE_90_DAYS` | Цена тарифа 90 дней в копейках. |
| `PRICE_180_DAYS` | Цена тарифа 180 дней в копейках. |

Секретные ключи и URL вашей инфраструктуры храните только в локальном `.env` или менеджере секретов. `.env.example` содержит только демонстрационные значения.

### Настройка 3X-UI

Настройте в панели рабочий inbound VLESS и разрешите доступ к API панели с хоста бота. Укажите его ID в `XRAY_INBOUND_IDS`. `XRAY_PANEL_URL` должен указывать на базовый адрес, который доступен боту; API-пути `/panel/api/...` добавляются кодом. `XRAY_SUB_URL` должен быть публичным адресом подписок, доступным клиентским приложениям.

Реализация использует API-токен в Bearer-заголовке и методы получения клиента по Telegram ID, добавления клиента и обновления срока. Сверьте API и настройки авторизации с вашей версией 3X-UI и [коллекцией YooKassa/3X-UI, использованной при разработке](https://documenter.getpostman.com/view/5146551/2sBXwnsBko). На тестовом inbound проверьте создание, продление и получение subscription URL до запуска приёма платежей.

### Запуск локально

В PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m bot.main
```

При первом запуске бот создаст таблицы `payment_orders` и `sent_reminders`, а также `tg_users`, если её ещё нет. Существующие таблицы и данные не очищаются. Убедитесь, что указанная PostgreSQL БД предназначена для бота и что резервное копирование настроено отдельно.

### Запуск через Docker

Установите Docker с поддержкой Compose, создайте `.env` и запустите:

```powershell
docker compose up -d --build
docker compose logs -f bot
```

Для остановки:

```powershell
docker compose down
```

Compose запускает только бота: PostgreSQL должен быть запущен отдельно и доступен по адресу из `DATABASE_URL`. Текущая конфигурация использует `network_mode: host`; проверьте поддержку host-сети вашей ОС и Docker-окружением. Для Docker Desktop на Windows может потребоваться адаптировать сетевой режим и адрес PostgreSQL.

## Использование

- `/start` — регистрация и главное меню.
- `/plan` — выбор тарифа и создание платежа.
- `/profile` — просмотр ключей и срока действия.
- `/help` — инструкция подключения.
- `/admin` — админ-панель для ID из `ADMIN_IDS`.
- `/debug-delete CONFIRM` — отладочная команда удаления данных пользователей; доступна только администраторам и удаляет записи пользователей, платежей и напоминаний. Используйте с осторожностью.

После создания оплаты бот периодически опрашивает YooKassa. Webhook не требуется. Успешный платёж выдаёт/продлевает доступ и отправляет пользователю ключ; сведения о платеже хранятся в PostgreSQL для повторной обработки и защиты от повторной выдачи.

## Проверки

Запуск unit-тестов:

```powershell
python -m unittest discover -s tests -v
```

Для полноценной интеграционной проверки нужны доступные тестовые учётные данные YooKassa, тестовый inbound в 3X-UI и тестовая PostgreSQL БД. Не проводите оплату и проверку выдачи на рабочей базе/панели без предварительной резервной копии и тестового сценария.
